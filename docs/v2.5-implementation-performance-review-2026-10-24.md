# SARA Repository Implementation and Performance Review

**Review date:** 2026-10-24  
**Code state:** base commit `d1a17ad` plus the uncommitted worktree changes for the v2.5 runner and v2.4 runtime contract repair.  
**Python:** 3.12.14 on Windows  
**Purpose:** operational code and local performance assessment; not canonical-promotion evidence.

## Summary

The repository's automated contract suite passes locally: **396 passed**. The
v2.5 dialogue route can be invoked through the new CLI with explicitly injected
judgment and verification providers. A pre-existing v2.4 import/API mismatch
that prevented loading `sara_runtime` was repaired and covered by the suite.

SARA v2.5 is **not ready for canonical promotion**. The actual Crossref request
failed with `URLError` in this environment. Production model/verifier adapters,
durable authenticated review operations, independently adjudicated labels, and
a preregistered comparative evaluation are not evidenced. The promotion gate
therefore remains fail-closed.

## Local Python overhead benchmark

Method: Python 3.12.14, same Windows host, synchronous in-process calls,
deterministic injected providers, 50 warm-up calls and 750 measured calls per
path. Each sample measures one complete call with `time.perf_counter_ns()`.
The v2.3 and v2.4 rows execute a claim-verification request. The v2.5 rows
execute a dialogue turn and include judgment-contract validation; one skips
inference verification, the other includes a deterministic stub verifier.

| Path | Median | p95 | Mean | Serial calls/s |
|---|---:|---:|---:|---:|
| v2.3 execution facade | 0.0050 ms | 0.0055 ms | 0.0051 ms | 197,685.8 |
| v2.4 integrated runtime | 0.0298 ms | 0.0425 ms | 0.0326 ms | 30,713.8 |
| v2.5 dialogue, no inference route | 0.5917 ms | 1.0726 ms | 0.6888 ms | 1,451.8 |
| v2.5 dialogue, inference plus stub verifier | 0.9893 ms | 1.3735 ms | 0.9878 ms | 1,012.4 |

These paths do different work, so the figures are **not a controlled speedup
comparison**. In particular, no model-generation, network verification,
database, or durable event-sink latency is included. The results establish only
that the local orchestration path completes at sub-millisecond average latency
with stubs on this host; production latency and cost remain unmeasured.

## Promotion gate assessment

Running `evaluate_canonical_promotion` against
`SARA_v2.5/promotion_evidence_template.json` returns
`PROMOTION_BLOCKED`. Outstanding evidence includes:

1. A frozen candidate SHA and successful CI results bound to that exact SHA.
2. Independently adjudicated benchmark cases, a frozen protocol and thresholds.
3. Same-case v2.3/v2.4/v2.5 comparison results with raw outputs and uncertainty.
4. Live host/provider tests, including timeout, malformed output and partial failure.
5. Authenticated reviewer authorization and durable storage/recovery evidence.
6. Explicit human canonical-release approval after the evidence gates pass.

The synthetic Preflight set and the local stub benchmark are development
fixtures; neither can satisfy independent performance or research-quality
promotion claims. Keep v2.4 canonical and v2.5 at user-led trial status until the
items above are resolved.
